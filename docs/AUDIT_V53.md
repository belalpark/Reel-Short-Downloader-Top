الاستنتاج: تظل الإضافة فهرسًا وتشخيصًا محليًا لصفحات يفتحها المستخدم؛ لا تُعتبر روابط HLS المرصودة دليلًا على تطابق الحلقة أو تصريحًا بالتنزيل. هذا استنتاج المراجعة الأصلية؛ راجع تحديث 0.2.1 أدناه للتحقق اللاحق من تشغيل حلقة مدفوعة.


## تحديث 0.2.0 / الإضافة 5.4.0

أزيل رمز الربط واختيار CSV من مسار الاستخدام الأساسي. ينقل الملحق الفهرس إلى Inbox خاص بالمستخدم، ويقرأ التطبيق تحديثاته تلقائيًا بمعرف مستقل لكل تحديث. إعادة فحص الناقص محدودة بثلاث جولات وتأخير متزايد، مع إيقاف قابل للتحقق. الجلسة الجديدة تحدّث الروابط المؤقتة، وإعادة تشغيل التطبيق تُلغي الفحص القديم. بقيت الملفات الأصلية v5.3 دون تعديل، وبقيت اختبارات ترحيل 45 حلقة و8 روابط ومرشحات HLS ضمن اختبارات التراجع. نتائج التنفيذ الفعلية وحدودها في [STATUS](STATUS.md).

## تشخيص التوقف عند المدفوع — 0.2.1 / الإضافة 5.4.1

تاريخ التشخيص: 15 نوفمبر 2026. أكّد المستخدم أن الحلقة ٩ تعمل داخل Edge. جرى فتحها بالطريقة المعتادة وتأكد تقدم تشغيل فيديو blob، مع ظهور قائمة HLS ومقاطعها ضمن الموارد التي طلبها المشغّل. بعد تنقل SPA، احتوت `__NEXT_DATA__` أيضًا بيانات مسلسل سابق؛ لم يكن الاستناد إلى تلك البيانات وحدها صالحًا لتحديد الحلقة الظاهرة. لا تُحفظ هنا عناوين محتوى المستخدم أو روابطه أو صوره أو بيانات جلسته.

كان 0.2.0 لا يرقّي مرشحات HLS إلى MediaURL حتى عندما تعمل الحلقة فعليًا، ويقرأ سجل Resource Timing محدود السعة، ولذلك يمكن أن ينجح مع الحلقات ذات الروابط الصريحة ويتوقف بعدها. أضيف مراقب مستمر منذ document_start، ومحلل محافظ لقوائم VOD المرصودة، وربط بالمدة ومقاطع طلبها المشغّل بعد الانتقال إلى الحلقة. تظل المرشحات المجردة غير قابلة للتنزيل، ولا يتضمن التحقق طلب مفاتيح أو معالجة DRM. مقارنة origin/path تمنع تدوير query token من إعادة نسب مصدر مثبت إلى حلقة أخرى.

أضيف اختبار تشغيل HLS حقيقي عبر hls.js، واختبار تنزيل HLS بواسطة أدوات Windows مع مطابقة إطارات الفيديو، وحالات تراجع للبيانات القديمة والمرشحات المسبقة وغموض المصدر. توثق نتائج التشغيل الفعلية وحدودها في [STATUS](STATUS.md)؛ تشغيل حلقة المستخدم في Edge لا يثبت بعد تنزيل النسخة الجديدة على جهازه.

## متابعة الحلقة والاستئناف — 0.2.2 / الإضافة 5.4.2

طلب المستخدم إعادة محاولة الحلقة نفسها حتى ينجح تنزيلها، واستئناف غير المكتمل فقط. أظهرت الصور أيضًا صفوفًا مكتملة بجانب «لم يظهر بعد» وعداد انتظار يشمل المحفوظ. أظهر الكود أن الانتقال المتعثر مرتين يوقف الفحص، وأن بداية الجلسة تعيد فهرسة جميع الصفوف، وأن سجل المكتملات لا يُحفظ حتى نهاية دفعة التنزيل.

أضيف مسار متتابع للتطبيق: أول حلقة غير محفوظة ← التقاط جديد ← تنزيل وفحص ← إقرار نجاح للتبويب ← الحلقة التالية. فشل الفتح أو المصدر أو التنزيل يعيد الحلقة ذاتها مع تأخير 3–60 ثانية دون حد ثابت لعدد المحاولات. تقييد الطلبات يفرض دقيقة انتظار. يبقى زر الإيقاف فعالًا أثناء المهلة وانتظار التنزيل، ولا يتضمن المسار فتح عناصر شراء أو تغيير حقوق الوصول.

يُحفظ المكتمل فور نتيجة الحلقة، ويُرسل عند الاستئناف إلى الملحق ليستثني صفحاته. ملفات أقدم مكتملة وغير مسجلة تُستعاد من مجلد المسلسل المطابق بعد فحص FFprobe، مع تجاهل part وinvalid والمسلسلات الأخرى. الفحص المحلي يجري في الخلفية قبل بدء التبويب؛ إيقاف المستخدم يلغي البدء اللاحق. الروابط المؤقتة القديمة لا تُعاد للاستخدام، ويحمل كل التقاط جديد معرفًا مستقلًا ليسمح بإعادة المحاولة حتى مع ثبات URL.

فُصلت حالة «محفوظ على الجهاز» عن غياب رابط حديث، وأُصلح عداد المتبقي. عند نقل ملف غير صالح بمخرج ناجح، تُحفظ نسخته الأخيرة بلاحقة invalid ويُحرر اسمه النهائي كي لا تمنع no-overwrites إصلاحه.

الاختبارات الجديدة تغطي 46 ملفًا مكتملًا ثم تعثر فتح 47 مرتين، وفشل تنزيلها وتجديد التقاطها، ثم إيقاف 48 وإعادة إنشاء receiver وwatcher واستئناف 48 فقط. يوجد اختبار Windows بأدوات التنزيل الفعلية لإصلاح ملف غير صالح واستعادة سجل قديم ناقص. نتائج التشغيل النهائي وحدود التحقق في [STATUS](STATUS.md).


## مكتبة المسلسلات — 0.3.0 / الإضافة 5.5.0

فُصلت فهرسة المسلسلات والتقاط المصادر عن تنزيل الملفات. تحفظ قاعدة SQLite معرف المسلسل ورقم الحلقة وصفحتها والمصدر المتغير وجيل التقاطه وآخر تحقق وصلاحيته المعلنة وحالة الملف. لا يعيد وصول snapshot سابق ترقية مصدر متعذر أو إسقاط تحقق أحدث؛ تحديثات الفحص مشروطة بجيل المصدر. تُستورد الفهارس القديمة مرة واحدة وتبقى سجلات الملفات المكتملة مشتركة بين المسلسل الحالي والمكتبة.

المصدر الملتقط ليس رابطًا موثقًا بعد: يلزم تقدم تشغيل الحلقة في المتصفح، ثم طلب محدود مستقل يفحص ترويسة الفيديو أو قائمة VOD المباشرة ومواقع مراجعها. تُرفض قوائم DRM والمصادر الأجنبية والعناوين المحلية، ولا تُطلب مفاتيح ضمن التحقق. الرابط الذي لا يعلن صلاحية يبقى مجهول المدة. عند فشل المصدر تُعاد صفحة المسلسل أو الحلقة بالطريقة المعتادة، دون إنشاء معرفات محتوى أو طلب واجهات خاصة. يحافظ التنزيل على فحص FFprobe قبل تسجيل كل ملف مكتمل.

أظهر فحص DOM حي لفهرس ReelShort أن بطاقات المسلسلات قد تشير مباشرة إلى الحلقة الأولى، وأن الفهرس يحتوي روابط shelf. لذلك يدعم الجمع روابط movie وfull-episodes وepisodes، ويتبع روابط shelf الظاهرة في تبويب واحد مع التمرير وزر المزيد العادي. الحد في الجولة ١٠٠٠ مسلسل و٤٠ صفحة؛ لا ادعاء بحصر كامل الخادم. يُحسب تعذر الفهرس على انقطاع التقدم، حتى لا تنهي مهلة إجمالية جولة صفحات طويلة ما زالت تعمل.

زر إعادة الربط يفحص المتطلبات ويعيد تنفيذ إضافة الملحق عبر واجهة Edge العادية، ثم ينتظر اتصالًا مصادقًا جديدًا. يتوقف فتح صفحات التجديد أثناء إصلاح الملحق، ويستمر تنزيل المصادر الجاهزة. إغلاق التطبيق يحفظ طلب مواصلة المكتبة، بينما زر الإيقاف يلغيه. تتجاهل الاستعادة الملفات المكتملة الصالحة، وتعيد إدراج سجل ملف مفقود فقط.

تغطي الاختبارات فهرس ٦٠ مسلسلًا اصطناعيًا مع تكرارات، وتجاوز ٥٨ مصدرًا محفوظًا، وجمع المسلسلين الناقصين، ثم إغلاق تبويب المصدر وتنزيل ٦٠ عنصرًا وتجديد عنصر واحد فقط. يوجد اختبار Windows منفصل يستخدم yt-dlp وFFprobe الحقيقيين لتنزيل ٦٠ فيديو قصيرًا، وإعادة إنشاء التطبيق بعد ٣٠، وإكمال البقية دون إعادة الملفات السابقة، مع مقارنة بصمات جميع الملفات. نتائج التشغيل الفعلية وحدود قبول الحساب الحقيقي موثقة في [STATUS](STATUS.md).


## الجلسات التلقائية ومشكلة الانتظار — 0.4.0 / الإضافة 5.6.0

الصور المقدمة تظهر تعثر الحلقة ٣ رغم وجود رابط، بينما تعرض المكتبة مسلسلات مكتملة وأخرى ناقصة. وأفاد المستخدم بأن إعادة الربط تتيح تنزيل الحلقة المفتوحة. لا تتضمن الصور سبب HTTP أو سجل أداة التنزيل، ولم يتوفر تبويب ReelShort في المتصفح المتصل أثناء الفحص؛ لذلك لا يُنسب تعثر جهاز المستخدم إلى خطأ HTTP بعينه دون تقرير تشغيله.

أثبتت مراجعة المصدر أن زر ٣ كان يشغّل مسارًا ينتظر نجاح الحلقة نفسها دون حد ثابت، وأن حالة المسح مشتركة ولا تصلح لتشغيل عدة تبويبات بمسلسلات مختلفة. كان فحص المصدر يرسل سياق طلب مختلفًا عن أداة التنزيل، وكان رابط HTML يحتفظ بالأولوية حتى عندما يُثبت بث HLS الفعلي. وكان انتظار stdout الخاص بالعملية قد يحجز الطابور عند توقف البيانات.

أصبح زر ٣ يبدأ الفهرسة والالتقاط والتنزيل معًا. لكل واحدة من ٣ جلسات معرف مستقل مرتبط بالمسلسل والتبويب، ومفتاح تخزين منفصل، وnonce جديد لكل دفعة. تُرفض رسائل المسلسل أو التبويب الخطأ والرسائل المتأخرة بعد سحب الجلسة. كل دفعة تصل إلى ٦ حلقات؛ يليها تناوب العمل مع حفظ الناقص وتأجيل المتعذر. مسار patient السابق محفوظ للتوافق والاختبارات، ولم يعد المسار الافتراضي للزر ٣.

يفضّل مسار الجلسات الجديدة بث HLS الذي طابق التشغيل والمدة والمقاطع المرصودة على رابط HTML قديم. يعاد تحميل المستند بعد اختيار حلقة عبر SPA حتى يبدأ رصد الموارد من صفحة جديدة. تُكتم تبويبات التطبيق وحدها لتشغيلها في الخلفية. يبقى الفصل بين مرشح URL ومصدر موثق وملف مفحوص، ولا تُفك حماية DRM أو تُفتح واجهة شراء.

يُحفظ User-Agent المرصود دون معلومات الدخول، ويستخدمه فحص المصدر والتنزيل مع Referer وOrigin العاديين. يدعم ذلك ما توضحه [وثائق yt-dlp](https://github.com/yt-dlp/yt-dlp/wiki/FAQ) عن ارتباط بعض روابط الوسائط بسياق طلبها؛ لا يثبت هذا وحده سبب فشل الحلقة ٣. لا تُقرأ كوكيز المتصفح أو كلمات المرور.

أضيف مراقب لتقدم النسبة وحجم الملفات؛ لا يكفي تكرار سطر النسبة نفسها ليُعد تقدمًا. انقطاع التقدم يلغي المحاولة العالقة ويحرر الطابور. تُصنف أخطاء HTTP والشبكة والقرص والفيديو غير الصالح، وتُحفظ آخر ١٠٠ نتيجة منقحة محليًا، مع زر «نسخ تقرير المشكلة» داخل التفاصيل. لا ينقل التقرير روابط الفيديو أو token الربط أو كوكيز المستخدم إلى GitHub.

حُمي الإيقاف بجيل للجلسات: فحص ملفات كان جاريًا قبل الإيقاف لا يستطيع إطلاق تبويب جديد بعده. يستثني الاستئناف المكتملات ويبدأ بالمسلسلات المعروفة الأقدم ثم يتناوب الدفعات. حُدث مخطط قاعدة المكتبة بإضافة سياق الطلب دون حذف سجلات 0.3.0، وجُمعت عدادات الجدولة في استعلام واحد لتقليل إعادة قراءة كل مسلسل من الواجهة.

يتضمن الاختبار ثلاثة مسلسلات في ثلاثة تبويبات، مع بث HLS فعلي يسبق رابط HTML معطلًا، وفشل تنزيل متحكم به ثم إعادة تلقائية بينما تتقدم المسلسلات الأخرى. اختبار Windows مستقل يستخدم أداة التنزيل المضمنة مع رفض HTTP 403 وتوقف انتقال البيانات ثم نجاح مسلسل تالٍ، ويقارن بصمة الفيديو. النتائج الفعلية وحدود اختبار الحساب في [STATUS](STATUS.md).
