## مشكلة المستخدم وما عولج

تظهر الصور فشل تنزيل الحلقة ٣ رغم وجود رابط، وأفاد المستخدم بأن إعادة الربط تتيح تنزيل الحلقة المفتوحة. لم يتوفر سجل خطأ أداة التنزيل أو تبويب ReelShort للفحص في المتصفح المتصل. لذلك **لم يُثبت سبب فشل الحلقة ٣ بعينه على جهاز المستخدم**، ولا يُنسب إلى رفض اشتراك أو HTTP 403 دون التقرير الفعلي.

أظهرت مراجعة المصدر انتظارًا غير محدود للحلقة نفسها في مسار الزر ٣ القديم، وحالة مشتركة لا تصلح لعدة تبويبات، واختلاف سياق الطلب بين الفحص والتنزيل، وأولوية لرابط HTML حتى عند تأكيد بث المشغّل، وانتظارًا قد يعلق على stdout دون بيانات جديدة.

أصبح الزر **٣ — ابدأ التنزيل التلقائي** يبدأ الفهرسة والتقاط المصادر وتنزيل الناقص معًا. تعمل حتى ٣ تبويبات، لكل مسلسل جلسة وnonce وتخزين منفصل، وتُرفض الرسالة المتأخرة أو المرسلة من مسلسل أو تبويب آخر. كل دفعة تصل إلى ٦ حلقات ثم تتناوب المسلسلات. المتعثر يؤجل ويُعاد تلقائيًا ولا يحجز بقية الملفات. يبقى مسار patient السابق للتوافق؛ لم يعد المسار الافتراضي للزر ٣.

يفضّل مسار الجلسات بث HLS المثبت بمطابقة التشغيل والمدة والمقاطع على رابط HTML قديم، ويعيد المستند بعد انتقال SPA. تُكتم تبويبات التطبيق وحدها لتعمل في الخلفية. يتسق User-Agent المرصود مع Referer وOrigin بين الفحص والتنزيل؛ لا تُقرأ كلمات المرور أو كوكيز Edge.

مراقب عدم التقدم يتابع النسبة وحجم الملفات، ويُنهي العملية العالقة بدل حجز الطابور. تُعرض أسباب HTTP والشبكة والقرص والفيديو غير الصالح، ويُحفظ آخر ١٠٠ تشخيص منقح. **التفاصيل ← نسخ تقرير المشكلة** ينسخ التقرير دون روابط الفيديو أو بيانات الدخول. يلغي الإيقاف جيل الجلسات حتى لا يفتح فحص قديم تبويبًا بعده.
