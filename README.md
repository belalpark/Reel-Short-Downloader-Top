# Reel Short Downloader Top

[![Windows checks](https://github.com/belalpark/Reel-Short-Downloader-Top/actions/workflows/windows.yml/badge.svg)](https://github.com/belalpark/Reel-Short-Downloader-Top/actions/workflows/windows.yml)

تطبيق Windows **0.4.0** مع إضافة Edge **5.6.0**. بعد تجهيز الملحق وتسجيل الدخول، زر واحد يبدأ جمع المسلسلات والتقاط مصادرها وتنزيل الناقص. يعمل حتى **٣ تبويبات مستقلة**، لكل تبويب مسلسل وجلسة مرتبطة بروابطه وملفاته. المتعثر يُجدول لاحقًا ويستمر باقي الطابور. نتائج التحقق وحدوده في [STATUS](docs/STATUS.md).

## التحديث والاستخدام

1. أغلق النسخة القديمة وثبّت EXE على Windows 10/11 x64. أبقِ مجلد الحفظ السابق. الأدوات مضمنة؛ لا أوامر CMD أو PowerShell ولا تثبيت Python يدويًا.
2. اضغط **٢ — أضف الملحق** مرة بعد التحديث وانتظر «الملحق جاهز ومتصل تلقائيًا». يسجل المستخدم دخوله بالطريقة المعتادة داخل Edge. لا رمز ربط أو كلمة مرور داخل التطبيق.
3. اضغط **٣ — ابدأ التنزيل التلقائي**، أو زر **ابدأ السحب والتنزيل تلقائيًا** داخل المكتبة. يجمع الفهرس ثم يشغّل جلسات الالتقاط والتنزيل دون زري جمع وتنزيل منفصلين.

يكتم التطبيق صوت تبويباته المُدارة لتشغيل الفيديو في الخلفية. لا يغيّر إعدادات صوت تبويبات المستخدم الأخرى. يمكن متابعة حالة كل مسلسل ورقم تبويبه داخل المكتبة، والنقر مرتين لعرض حلقاته وآخر فحص وسبب التأجيل. زر **إيقاف المكتبة** يوقف الجلسات والطابور. إغلاق التطبيق يحفظ طلب مواصلة المكتبة؛ يستأنف عند فتحه بعد نجاح فحص المتطلبات.

الحفظ الافتراضي: **Downloads / Reel Short Downloader Top**، وكل مسلسل في مجلد مستقل. الملفات المكتملة الموجودة لا يعاد تنزيلها. عند المواصلة يُفحص الناقص فقط، وتبدأ المسلسلات المعروفة الأقدم قبل إدخالات الفهرس الجديدة، ثم تتناوب دفعات العمل.

## كيف يعمل السحب التلقائي

- يقرأ روابط المسلسلات وصفحات shelf الظاهرة في الموقع. لا يطلب واجهات مشاهدة خاصة ولا يخمن معرفات المحتوى.
- تُعطى كل جلسة هوية جديدة مرتبطة بمعرف المسلسل والتبويب. التخزين والرسائل منفصلة بين الجلسات، وتُرفض الرسالة المتأخرة أو المنسوبة لمسلسل أو تبويب آخر.
- عند توفر مصدر من تشغيل مؤكد يصل إلى المكتبة ويوقظ فحص الرابط فورًا. بعد اجتياز الفحص يدخل طابور التنزيل، وبعد فحص الملف بواسطة FFprobe يُحفظ نجاحه مباشرة.
- يفضّل مسار الجلسات بث HLS المتطابق مع الفيديو الذي يشغله الموقع على رابط HTML قديم، عندما تتأكد المدة والمقاطع المرصودة. يفتح صفحة جديدة بعد اختيار الحلقة لتجنب بيانات SPA القديمة.
- كل دفعة تلتقط حتى ٦ حلقات ناقصة ثم تُحرر الجلسة للبقية. تقييد الموقع يفرض مهلة، والتعثر لا يحجز كل المسلسلات في حلقة تحديث واحدة.
- تنزيل الروابط الصالحة مستقل عن بقاء Edge مفتوحًا؛ عند الحاجة لتجديد رابط يُفتح الموقع. قد يلزم استكمال تسجيل الدخول إذا انتهت الجلسة. أبقِ الكمبيوتر والتطبيق يعملان والإنترنت متاحًا أثناء التنزيل.

## التعثر والتشخيص

| الحالة | التصرف |
| --- | --- |
| HTTP 401/403 أو رابط لم يعد موجودًا | إظهار سبب الرفض، وتأجيل الحلقة، وتجديد المصدر من صفحتها عند المحاولة التالية |
| انقطاع الشبكة أو تقييد الطلبات | مهلة قبل المحاولة التالية؛ استمرار الملفات الأخرى المتاحة |
| توقف وصول البيانات | مراقب يلغي المحاولة العالقة بعد مهلة عدم تقدم، ثم يحرر الطابور |
| ملف ليس فيديو صالحًا | عدم اعتباره مكتملًا، وحفظ آخر نسخة invalid ثم تجديد المصدر |
| نقص المساحة أو فشل الكتابة | سبب واضح وتأجيل؛ يلزم إصلاح مساحة القرص أو مسار الحفظ |
| جلسة التقاط لا تتقدم | تحريرها وإعادة إدراج الناقص مع استمرار الجلسات الأخرى |

يُحتفظ بآخر ١٠٠ تشخيص محليًا دون روابط الفيديو الموقعة أو بيانات الدخول. عند تكرار مشكلة فعلية افتح **التفاصيل ← نسخ تقرير المشكلة** وأرسل النص؛ لا تحتاج أوامر أو تصدير CSV. زر **إعادة الربط والفحص** يعيد فحص المتطلبات وتحديث ربط الملحق مع حفظ التقدم.

إذا منع Edge الإضافة بسبب سياسة جهاز أو تغيرت واجهته، يظهر السبب ومجلد الملحق والخطوة اليدوية. لا يغير التطبيق سياسات الجهاز. التفعيل يستخدم واجهة Edge العادية وفق [توثيق Microsoft](https://learn.microsoft.com/microsoft-edge/extensions-chromium/getting-started/extension-sideloading).

## البيانات والحدود

- تبقى قاعدة المكتبة والفهرس والسجلات في `%LOCALAPPDATA%\ReelShortDownloaderTop`. تُرقى قاعدة 0.3.0 دون حذف المسلسلات أو سجل الملفات المكتملة.
- الربط المحلي على `127.0.0.1:18765` مصادق عليه بإصدار الملحق وهويته وtoken خاص بالمستخدم. لا تُقرأ كلمات مرور أو كوكيز Edge، ولا تُرسل إلى GitHub.
- يحتفظ المصدر بسياق الطلب العادي مثل User-Agent وReferer وOrigin حتى يتسق الفحص والتنزيل. لا يعني وجود رابط أن الخادم سيقبله أو أن صلاحيته دائمة.
- الفهرسة حتى ١٠٠٠ مسلسل و٤٠ صفحة في الجولة، و٣ جلسات متزامنة. لا تضمن حصر كل ما في خوادم الموقع أو تنزيل حلقة غير متاحة للحساب. لا معالجة لمفاتيح DRM أو تجاوز لحقوق الوصول.
- وجود مسلسل في المكتبة يختلف عن التقاط روابطه، وتوثيق الرابط يختلف عن اكتمال الملف. النجاح يُسجل بعد التنزيل وفحص الفيديو.
- اختبارات المتصفح والتنزيل تستخدم بيانات اصطناعية. قبول مكتبة الحساب الحقيقية، وجهاز Windows 10/11 وDPI المختلف، والتشغيل الطويل متطلبات منفصلة موضحة في [قائمة القبول](docs/ACCEPTANCE.md).

## التثبيت والبناء

المثبّت يفحص Windows وEdge وسلامة ملفات الحزمة وتشغيل yt-dlp وFFmpeg وFFprobe وصلاحيات البيانات والحفظ قبل Finish. نقص المتطلبات يرجع الرمز 12. تفعيل الملحق يتم داخل التطبيق من الزر ٢. النسخة التطويرية غير موقعة بشهادة.

المثبّت وحده متاح في أحدث تشغيل ناجح لـ[تنزيل المثبّت](https://github.com/belalpark/Reel-Short-Downloader-Top/actions/workflows/installer-download.yml). الحزمة الكاملة والنسخة المحمولة في [بناء Windows](https://github.com/belalpark/Reel-Short-Downloader-Top/actions/workflows/windows.yml). تُطابق بصمات البناء الأصلي قبل فصل المثبّت.

للمطور على Windows x64 مع Python 3.12 وNode 22 وInno Setup 6:

```powershell
python -m pip install -r build-requirements.txt
python -m unittest discover -s tests -p 'test_*.py'
node --test tests/extension.test.cjs
.\scripts\Download-Dependencies.ps1
python scripts/package.py
& 'C:\Program Files (x86)\Inno Setup 6\ISCC.exe' installer\ReelShortDownloaderTop.iss
```

تثبت أدوات الحزمة ببصمات `vendor-lock.json`. يعمل CI على Linux وWindows، ويختبر الجلسات الثلاثة ومصادر HLS وفشل التنزيل والاستئناف، ثم EXE وEdge والمثبّت الفعليين. اختبار المتصفح يستخدم Playwright وhls.js وChrome for Testing بترميز H.264/AAC؛ يهيئها workflow تلقائيًا.

ملفات v5.3 الخمسة عشر محفوظة دون تغيير في `legacy/v5.3`. راجع [مراجعة المصدر](docs/AUDIT_V53.md) و[إشعارات المكونات الخارجية](THIRD_PARTY_NOTICES.md).
